# Codex 自动标题与大图片历史本地验收

日期：2026-09-23。基线：`ba0e263`。本记录验证本次开发首轮 Linux 本地候选二进制，
不代表已发布或已替换常用的本地服务。二进制与生产源文件树 SHA-256、脱敏结果保存在
[验收数据](codex-title-large-body-2026-09-23.json)。

## 改动与边界

- 单请求默认上限由 10 MiB 提高到 32 MiB。总请求体预算仍为 128 MiB，最多 16 个
  在途请求；上传结束前按最大请求体预留，因此同时未完成上传最多 4 个。
- 兼容模式接受单字符串对象的有界 JSON Schema，用于 Codex 自动标题。上游仍生成
  文本，本地缓冲、转换、校验后返回 JSON，并报告兼容标记。严格保真模式保持拒绝。
- 真实 Codex 0.156.1 的标题线程附带 collaboration namespace。当前声明经过既有
  校验并完整投影；任何本轮工具调用在输出前失败，不执行工具。历史工具调用/结果、
  续接和非文本输入不在该元数据能力范围内。
- 流式与非流式均在收集时限制 64 KiB 可见文本，超限后取消上游并等待清理，之后才
  释放账号及 HTTP 准入预算。每次元数据请求最多派发一次上游推理。

## 真实本地验收

所有探针使用独立端口、独立账号/数据库副本及合成内容。没有重放用户的原始会话、
提示词或截图。Codex 使用网关的 models 目录投影，模型为 `gpt-5.6-sol`。

| 验收                                      | 结果                                                                                               |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 14 张历史工具图片请求                     | 11,025,119 bytes，HTTP 200，一个 `response.completed`，预期文本匹配                                |
| 真实 Codex 调用 14 次 `view_image` 后继续 | 后续请求 11,126,975 bytes，HTTP 200，客户端正常退出，预期文本匹配                                  |
| 真实 Codex TUI 自动标题                   | 自动请求和普通对话均 HTTP 200，各一个完成事件、零失败事件                                          |
| 标题持久化                                | TUI 正常退出后重新读取 `session_index.jsonl`，11 字符标题与生成值 SHA-256 一致；手动重命名调用为 0 |

Codex 此版本的显式线程名称保存在 session index；SQLite 的 `title` 字段可能仍是首条
用户消息，因此验收同时关联隔离线程身份并检查实际名称存储。

## 回归与质量检查

修复前，标题请求因 `text.format` 返回 400；照搬旧 worktree 后，真实 TUI 又因工具
声明返回 400。两种完整请求形状均已进入常规回归测试。大请求回归在旧 10 MiB
默认值下返回 413，在新默认值下完成；显式旧上限、超过 32 MiB、未授权请求、预算耗尽
及取消后恢复仍受到验证。非流式缓冲回归先证明超限后仍继续读取，再验证及时停止和
清理期间不提前释放租约。

`make pre-ci` 通过：2,525 项测试、11,043 个断言、零失败；仓库口径覆盖率为
26,160 / 27,414 行（95.43%），高于 93% 门槛。格式、类型、lint、文档链接、脚本语法、
安全检查、覆盖率配置一致性及 npm 构建均通过；独立二进制构建也通过。

后续 Windows CI 发现了三项平台差异：大上传提前关闭时 fetch 隐藏 413、孤立 surrogate
的 Buffer 字节数不一致、POSIX mode 不能表达 Windows ACL。后续修订改用原始 HTTP
状态验证、共享的确定性 UTF-8 计数以及真实 Windows SID/DACL 检查，保留原有断言，
另补跨平台负例。本记录中的候选哈希和测试计数仍对应首轮 Linux 证据；后续提交的
原生平台检查由 [PR #104](https://github.com/sunerpy/kiro-provider/pull/104) 记录。

token、账号信息、会话标识、原始提示词、标题正文或图片数据。
